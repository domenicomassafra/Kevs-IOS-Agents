# Distributed production topology — Linux MiniPC + macOS device workers

## Authority split

The production authority is the Linux MiniPC. It owns the dashboard/API, PostgreSQL, pg-boss schedules, campaigns, account policy, analytics and canonical uploaded media. It runs under Docker Compose and can stay online independently of any Mac or iPhone.

macOS hosts are execution nodes only. A Mac owns Xcode signing, Appium/XCUITest, WebDriverAgent, USB-attached iPhones and the scheduler workers for those devices. The MiniPC never needs Xcode and a Mac no longer needs to host the canonical web UI.

The control plane reaches each Mac through the authenticated device-worker gateway. Screenshot, accessibility, MJPEG and remote input are proxied through that gateway; WDA ports remain loopback-only on the Mac. Device workers connect to the MiniPC PostgreSQL instance to claim their per-device pg-boss queues. Scheduled media is fetched on demand from the MiniPC through a separate authenticated internal endpoint and verified by size + SHA-256 before use.

## Network model

Use a private network or, preferably, Tailscale. Do not expose Appium, WDA, PostgreSQL or the device-worker gateway to the public Internet.

The dashboard container intentionally binds `127.0.0.1` on the MiniPC. On the owner's current MiniPC the production defaults use local port `4050`, PostgreSQL `55432`, and dedicated Tailscale HTTPS port `18443` to avoid existing CreatorOS/Buzz services. `deploy/setup-minipc.sh` configures that dedicated Tailscale Serve listener when Tailscale is installed, so the UI/API gets tailnet HTTPS without exposing Fastify publicly. PostgreSQL listens on loopback plus the MiniPC Tailscale address generated by the setup script; it is not bound to the public/LAN wildcard.

## MiniPC

```bash
cp .env.minipc.example .env.minipc
# edit worker URL(s), secrets and private PostgreSQL bind address
./deploy/setup-minipc.sh
```

`docker-compose.production.yml` runs PostgreSQL 17 and the control-plane container with persistent state in `.runtime/minipc` plus the PostgreSQL named volume. Both services use `restart: unless-stopped`.

The control-plane image intentionally installs npm dependencies with lifecycle scripts disabled. Native OCR and iPhone automation binaries are execution-node concerns and are not loaded by the Linux control plane. Dashboard JavaScript is compiled during the image build (not on every container start), after which a real `tsx` import smoke test checks the API server. Runtime can therefore stay unprivileged and treat the application tree as immutable.

The control-plane worker list uses:

```text
PHONE_FARM_DEVICE_WORKERS=macstudio=http://macstudio:3010,othermac=http://othermac:3010
```

The control plane periodically refreshes those inventories. A sleeping/offline Mac does not prevent the MiniPC from starting; its devices simply appear disconnected.

## Mac device worker

```bash
cp .env.device-worker.example .env
# point DATABASE_URL and PHONE_FARM_CONTROL_PLANE_URL at the MiniPC
# copy the two matching shared tokens from .env.minipc
./deploy/setup-device-worker.sh
```

`PHONE_FARM_ROLE=device-worker` changes launchd packaging to install only Appium, WDA supervision, the pg-boss execution worker and the authenticated HTTP device gateway. The web dashboard is deliberately omitted on that Mac.

The local `devices.json` remains the authority for secrets and physical endpoint details such as the unlock passcode and local WDA/MJPEG ports. The MiniPC mirror never receives the passcode.

## Operator access

Once deployed, the normal operator path is:

```text
browser / Hermes / MCP / Discord
              |
              v
      MiniPC control plane
       |       |        |
 PostgreSQL  media   device gateway calls
                         |
                         v
                  macOS execution node
                  Appium + WDA + iPhone
```

This means the farm can be operated from a MacBook, Mac Studio, another workstation or an agent client without logging into the MiniPC desktop.

## Readiness commands

On the MiniPC host:

```bash
docker compose --env-file .env.minipc -f docker-compose.production.yml ps
docker compose --env-file .env.minipc -f docker-compose.production.yml exec -T control-plane npm run doctor:control-plane
```

On every Mac execution node:

```bash
npm run doctor:device-worker
npm run service -- status
```

The remaining physical acceptance gate is still real hardware: full Xcode, signed modern WDA/XCUITest, reachable PostgreSQL, a trusted iPhone, and a successful `npm run acceptance:live` receipt.
